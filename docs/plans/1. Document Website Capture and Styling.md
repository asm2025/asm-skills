# Document Website Capture and Styling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `document-website` capture pages that scroll inside a box, build Word/HTML/PDF tutorials from a Word template or a reference document's look, color markers from options or a style file with automatic contrast, and expose every Playwright MCP browser mode.

**Architecture:** Two new helper modules sit next to the existing CLIs: `style_file.py` (one JSON style file read by both scripts) and `pdf_engines.py` (Word, LibreOffice, and Chrome converters behind one interface), plus `contrast.py` for the auto-contrast math. `build_docx.py` gains `--template`, `--style`, `--css`, `--pdf-engine`, and `.pdf` output; `annotate.py` gains `--style`, `--color`, `--bg`, `--fg`, and `--no-auto-contrast`. The full-page fix and browser modes are agent workflow, so they live in `SKILL.md` and new `references/` files, with plugin config changes in `plugin.json`.

**Tech Stack:** Python 3 standard library, Pillow, python-docx; PowerShell COM for Word; `soffice`; headless Chrome or Edge; `@playwright/mcp`.

**Spec:** `docs/specs/1. Document Website Capture and Styling.md`

## Global Constraints

- Exit codes stay: `0` saved, `1` saved with problems or could not write, `2` invalid input and nothing written. No tracebacks for user mistakes.
- No new required Python package for the skill. `requirements.txt` stays `Pillow` and `python-docx` (plus the optional right-to-left pair). The verification harness may add `pypdf` to its own venv only.
- `.pdf` is never a default output and no PDF engine is launched unless `--output` ends in `.pdf`.
- Every auto-contrast color change prints a `[warn]` naming the marker, the field, the old color, the new color, and both contrast ratios.
- Saved sign-in files never go in a git-tracked folder; docs call them a live session secret.
- Script paths in `SKILL.md` use `<skill-dir>`; `SKILL.md` stays short and detail goes in `references/`.
- US English in docs, warnings, and errors.
- A marker-schema change updates `annotate.py` and `references/annotation-spec.md` together; a `steps.json` or build-option change updates `build_docx.py` and `SKILL.md` step 5 together; a dependency change updates `requirements.txt`, `SKILL.md` Dependencies, and README Requirements together.
- Every behavior change gets a recipe in `.claude/skills/verify-document-website/features/` in the same commit, and `features/README.md` lists it (every task that creates a recipe also adds its row to `features/README.md`).
- Text drawn inside circles and labels must reach 3.0:1 against its fill (WCAG large-text minimum; marker text is bold and large). Owner decision 2026-11-04, replacing the spec's earlier 4.5: at 4.5 the built-in white on `#E53935` (4.23:1) would flip every default marker to black text with a warning.
- Test inputs and outputs live in the harness `RUN` folder or `!tmp/`, never in tracked folders.
- Commit messages: plain-sentence subject like the repo history, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A broken style file** (UTF-8 with BOM, invalid JSON, a top-level array, a misspelled key) should give one clear `[error]` or `[warn]` naming the file and key, never a traceback. Tests: Task 1, bullets `style-errors`.
2. **A template that is not really a Word file** (a renamed PDF, a `.doc`, a missing path) should exit `2` with `--template is not a Word document`, writing nothing. Tests: Task 3, bullet `template-errors`.
3. **A `.pdf` output already open in a PDF viewer** should exit `1` with the same "close it and run again" message as a locked `.docx`, before any engine starts, and leave no temp files behind. Temp files are kept (and their path printed) only when the engine itself fails. Tests: Task 5, bullets `pdf-locked`, `pdf-engine-fail`.
4. **A marker partly or wholly off the image** has few or no background pixels to sample; auto-contrast must skip it quietly and the existing off-image warning must still appear. Tests: Task 2, bullet `contrast-offimage`.
5. **Paths with spaces and non-ASCII letters** for the template, output, and PDF engines (PowerShell quoting, `file://` URIs for Chrome) should work. Tests: Task 5, bullet `pdf-paths`.
6. **A saved sign-in file must never land in a tracked folder**, whatever folder the screenshots went to. Tests: Task 8, `references/browser-modes.md` rule and the spec-examples run in Task 9.

### Task 2: Auto-contrast for markers

**Files:**
- Create: `skills/document-website/scripts/contrast.py`
- Modify: `skills/document-website/scripts/annotate.py` (`annotate()` drawing loop)

**Interfaces:**
- Consumes: Task 1 `annotate(..., auto_contrast, min_contrast, palette)`, `resolve()`, `parse_color`.
- Produces (`contrast.py`):
  - `BUILTIN_PALETTE = ["#E53935", "#1565C0", "#FDD835", "#000000", "#FFFFFF"]`
  - `luminance(rgb) -> float` (WCAG relative luminance), `ratio(a, b) -> float` (WCAG contrast ratio)
  - `ring(footprint: Image.Image, width: int = 3) -> Image.Image`: mode `L` mask of pixels within `width` of the footprint but outside it (`MaxFilter(2*width+1)` minus footprint).
  - `score(background: Image.Image, mask: Image.Image, rgb) -> float | None`: 20th percentile of `ratio(rgb, pixel)` over mask pixels; `None` when the mask is empty.
  - `choose(background, mask, preferred_rgb, palette: list, min_contrast: float) -> tuple[rgb, float]`: `preferred` if it passes; else the first palette color (style palette, then `BUILTIN_PALETTE`) that passes; else the highest-scoring one.
  - `TEXT_MIN_CONTRAST = 3.0`; `text_on(fill_rgb, fg_rgb) -> rgb`: `fg` if `ratio(fg, fill) >= TEXT_MIN_CONTRAST`, else black or white, whichever contrasts more with `fill`. The text threshold does not follow `min_contrast`. (Reference numbers: white on `#E53935` is 4.23:1, so default markers keep white text.)
- vdw: `fixture --kind contrast` writes the `--size` image (default 1280x720) as four full-height strips, each a quarter of the width: orange `(232,131,58)`, black `(0,0,0)`, white `(255,255,255)`, gray `(119,119,119)`. The existing fixture becomes `--kind form`, the default, byte for byte unchanged.

Per-marker algorithm (in `annotate()`): resolve the marker; if auto-contrast is on for it (global on, style `auto_contrast` not false, marker `auto_contrast` not false):
1. Draw it on one scratch `Canvas` that is reused for every marker. The scratch canvas's warnings are discarded, so font and right-to-left warnings print once, from the real draw.
2. Take the bounding box the drawer returns, grow it by the ring width plus 1, and clip it to the image. Crop the scratch alpha and the original screenshot to that box; build `ring()` and `score()` on the crops only, never on the full image (tall full-page images make full-size filters take seconds per marker). Then clear that box on the scratch overlay.
3. `choose()` the main color (`color` for arrow and box, `bg` for circle and label), then for circle and label apply `text_on(bg, fg)`.
4. Draw for real on the output canvas with the settled colors.

Empty ring or a box fully off the image: skip quietly. Warning format: `marker <n> (<type>): <field> #RRGGBB has <x.x>:1 contrast on the background; drew #RRGGBB instead (<y.y>:1).` and for text `marker <n> (<type>): fg #RRGGBB has <x.x>:1 contrast on bg #RRGGBB; drew #RRGGBB instead (<y.y>:1).`

Catch every way a non-Word file fails (python-docx `PackageNotFoundError`, `zipfile.BadZipFile`, `KeyError`, `ValueError`) and map it to that message. python-docx refuses `.dotx` (its main part has the template content type), so read the package into a `BytesIO`, rewrite `application/vnd.openxmlformats-officedocument.wordprocessingml.template.main+xml` to `...document.main+xml` in `[Content_Types].xml`, and open the rewritten bytes. Without a template, output is unchanged (`Normal` 11 pt, title centered, captions centered italic gray 9 pt directly as today). Images stay centered in every case.

  const se = document.scrollingElement || document.documentElement;

  const boxes = [];

  const name = e => e.tagName.toLowerCase() + (e.id ? '#' + e.id : '') +
    [...e.classList].slice(0, 3).map(c => '.' + c).join('');
  const main = boxes[0];

  if (main) { main.el.setAttribute('data-dw-scroll', 'main'); main.el.scrollTop = 0; }
