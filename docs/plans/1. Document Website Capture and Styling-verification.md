# Document Website Capture and Styling: human verification

Items only a person can do. Each entry: the item, why an agent cannot do it, and the trigger (when to do it). Mark an entry resolved with the result, and rename this file to `-verification-done.md` once every entry is resolved.

## 1. The storage tools show up after reinstalling the plugin

- **Item.** Reinstall the plugin (`/plugin marketplace update essential-skills`, then reinstall or reload), open `/mcp`, and confirm the `essential-skills` `playwright` server lists `browser_storage_state` and `browser_set_storage_state`. Also confirm the official `playwright` plugin's server is disabled, so only one Playwright server is active.
- **Why an agent cannot do it.** The agent cannot reinstall the plugin into the user's own Claude Code or read the user's `/mcp` panel. The recipe `modes-caps` proves the server lists the tools when started over stdio with `--caps=storage`, not that Claude Code's plugin loader passes the argument through.
- **Trigger.** The next real tutorial run after the plugin version `1.1.0` is installed.

## 2. Sign in to a real site, save it, restore it headless

- **Item.** In the headed Playwright window, sign in to a real site. Ask the agent to save the sign-in (it must use `<temp>/auth/<host>.json`, run `git check-ignore -q`, and warn that the file is a live session secret). Then restart the server with `PLAYWRIGHT_MCP_HEADLESS=true`, ask the agent to restore the sign-in with `browser_set_storage_state`, and confirm a protected page loads signed in. Delete the saved file afterwards.
- **Why an agent cannot do it.** It needs the user's real account and credentials, the user's own typing in the browser window, and a real live session. An agent must not hold or create a real sign-in file.
- **Trigger.** The next real tutorial run on a site that needs sign-in.

## 3. The `--extension` server driving the user's own Chrome

- **Item.** Install the Playwright extension in Chrome, register `claude mcp add playwright-chrome -- npx @playwright/mcp@latest --extension`, say "use my Chrome," and confirm the agent drives a real tab with the real sign-in.
- **Why an agent cannot do it.** It needs the extension installed in the user's browser, the user's approval of the connection prompt in that browser, and the user's signed-in profile.
- **Trigger.** The first time a tutorial needs the user's own signed-in browser.

## 4. LibreOffice PDF engine

- **Item.** On a machine that has LibreOffice, run the `pdf-libreoffice` bullet in `.claude/skills/verify-document-website/features/build-pdf.md`, and the `--pdf-engine libreoffice` path with a template.
- **Why an agent cannot do it.** LibreOffice is not installed on the development machine, so the LibreOffice code path was skipped and is untested.
- **Trigger.** Before relying on `--pdf-engine libreoffice` or on `auto` choosing LibreOffice, or the next full verification run on a machine with LibreOffice.

## 5. A real Word-authored `.dotx` template looks like the user's corporate template

- **Item.** Build a tutorial from the user's own corporate `.dotx` and open the result in Word. Check that headings, captions, headers, footers, and logos look like the user's template (brand fonts, theme colors, a logo in the header).
- **Why an agent cannot do it.** The recipe `template-word-authored` already builds a template through Word's own automation and checks styles, page setup, header, footer, and the Word-rendered PDF text. What is left is a person's judgment that the result matches a specific corporate template, and that template is not available to the agent.
- **Trigger.** The first time a user supplies their own corporate `.dotx` template.

## 6. Does a Claude Code `settings.json` `env` entry reach the plugin's Playwright server?

- **Item.** Set `PLAYWRIGHT_MCP_HEADLESS=true` (or another `PLAYWRIGHT_MCP_*` variable) under `env` in Claude Code's `settings.json` instead of the shell, restart the session, and check in `/mcp` or by taking a screenshot whether the server picked it up. `references/browser-modes.md` says to set the variables in the shell before starting the agent; this entry decides whether the `settings.json` route also works and whether the doc can say so.
- **Why an agent cannot do it.** It needs the user's own Claude Code settings file, a restart of the host that launches the MCP server, and a look at the real window or `/mcp` panel. The harness probe starts the server itself, so it cannot show what Claude Code passes to it.
- **Trigger.** The first time a user asks to set the browser mode from `settings.json`, or the next edit of `references/browser-modes.md`.
